# sunc-schedule-bot

Telegram-бот, который следит за расписанием занятий СУНЦ УрФУ и постит его в чат класса:
опрашивает сайт раз в `POLL_MINUTES`, присылает изменения, каждый день в `DAILY_HOUR`
публикует расписание на завтра (картинкой, с ДЗ из журнала в подписи) и отвечает на команды.

> **Безопасность:** файл `.env` (токены, пароли журнала) добавлен в `.gitignore`
> и в репозиторий не попадает. Никому не пересылайте свой `.env` — каждый подключает
>свою учётку от @BotFather и вход в журнал сам.

## Как найден источник данных

Страница <https://lyceum.urfu.ru/ucheba/raspisanie-zanjatii> (TYPO3) отдаёт пустую
таблицу: она заполняется JS по выбору класса/аудитории/преподавателя и дня недели.

1. Скачали страницу и вытащили все `src`/`href` — среди них оказался бандл
   `/typo3conf/ext/sunc_schedule/Resources/Public/dist/custom.js`.
2. В нём функция `ajaxSchedule()` строит URL и шлёт `$.ajax({type: "GET", dataType: "json"})`:

```js
var url = '/?type=11';
url += '&scheduleType=' + options.scheduleType.value;   // group | teacher | auditory
url += '&scheduleType=...' + '&weekday=' + options.weekday.value;  // 1..6
if (options.scheduleType.value == 'group')  url += '&group='  + options.group.value;
```

3. Воспроизвели запрос чистым `curl` — работает без сессии, кук и заголовков:

```bash
curl 'https://lyceum.urfu.ru/?type=11&scheduleType=group&weekday=4&group=22'
```

```json
{"type":"group",
 "lessons":[{"uid":16657,"subject":"Алгебра","auditory":"304","group":"10Н",
             "teacher":"Бондарь А. А.","subgroup":0,"number":1,"weekday":4}, ...],
 "diffs":[]}
```

### Эндпоинт

| Параметр | Значения |
|---|---|
| `type` | `11` (номер типаTYPO3, без него вернётся HTML страницы) |
| `scheduleType` | `group`, `teacher`, `auditory` |
| `weekday` | `1..6` = Пн..Сб; `0` и `7` (вс) → пустой `lessons` |
| `group` / `teacher` / `auditory` | числовые id из `<select data-name="...">` страницы |

Ответ — JSON в теле, хотя `Content-Type: text/html` (поэтому jQuery и просит
`dataType: "json"`). Коды ошибок не используются: несуществующий `group=9999` и
запрос вовсе без параметров возвращают `{"type":"group","lessons":[],"diffs":[]}`.

Справочники id парсятся со страницы (33 класса, 172 преподавателя, 59 аудиторий):
`10Н → 22`, `304 → 87`, `Бондарь А. А. → 154`. Проверяется на старте и обновляется раз в сутки.

Поля `lessons`: `subject`, `teacher`, `auditory`, `group`, `subgroup` (0 — весь класс,
1/2 — подгруппы), `number` (1..7), `weekday`. Поле `diffs` — тот же формат, на сайте
подсвечивается красным (замены/изменения); бот помечает такие уроки как «изменение».

Браузер (Playwright) не понадобился — обычного HTTP-запроса достаточно.

## Конфигурация

`.env` (образец — `.env.example`):

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `CHAT_ID` | чат класса: числовой id (`-100…`) или `@имя` |
| `CLASS` | класс, за которым следит бот (`10Н`, `11А`…) |
| `TZ` | часовой пояс, по умолчанию `Asia/Yekaterinburg` |
| `POLL_MINUTES` | период опроса, по умолчанию `10` |
| `DAILY_HOUR` | час поста расписания на завтра (вс–пт), по умолчанию `15` |
| `ADMIN_ID` | Telegram id администратора (нужен для `/проверить`, `/статус`) |
| `THREAD_ID` | ветка (topic) форума; надёжнее задать командой `/тема` внутри ветки |
| `LYCREG_LOGIN`, `LYCREG_PASSWORD` | вход в электронный журнал lycreg.urfu.ru (для ДЗ); пусто — ДЗ отключено |
| `DB_PATH`, `HORIZON_DAYS`, `LOG_LEVEL` | необязательные |

`.env` в `.gitignore`, токены в код не попадают.

### Форум-чат (несколько веток)

Если `CHAT_ID` — форум-супергруппа, все посты (15:00, изменения, `/пост`)
идут в ветку из `THREAD_ID`; команды в ответ всегда приходят в ту ветку,
где их написали. Настройка:

1. добавить бота в группу **администратором** (право публиковать сообщения);
2. написать в нужной ветке `/тема` — бот запомнит её и подтвердит.

Без `/тема` сообщения уйдут в «Общую» тему.

### Домашнее задание (lycreg.urfu.ru)

При заданных `LYCREG_LOGIN`/`LYCREG_PASSWORD` бот читает электронный журнал
и:

- при `/пост` (и в 15:00) кладёт ДЗ **в подпись к фото расписания** одним
  сообщением: `ДЗ на субботу 11.10` со списком заданий по урокам этого дня.
  ДЗ берётся от **последнего записанного в журнале урока** предмета строго до
  дня урока; если на этом уроке ДЗ не записано или ему больше 10 дней, предмет
  в подписи не показывается — устаревшее ДЗ (вроде трёхнедельной давности)
  в пост не попадает. Преподаватель и
  предмет сверяются с расписанием; текст-фолбэк (если картинка не
  отправилась) дублирует ДЗ в конце расписания;
- администратору доступна `/дз [день]` (без аргумента — завтра), чтобы
  проверить/получить ДЗ вручную.

Вход в журнал защищён капчей: когда токен истекает, бот присылает картинку
капчи **администратору в личку** и ждёт ответа-цифры (10 минут); пост в этом
случае задерживается до входа. Успешный вход сохраняется в базе, дальше бот
работает по токену. Ошибки журнала — в логе; сам пост расписания при
недоступном журнале уходит без подписи с ДЗ.

## Запуск

```bash
git clone https://github.com/Egkaz/sunc-schedule-bot.git && cd sunc-schedule-bot
python3.12 -m venv .venv
.venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env          # вписать BOT_TOKEN, CHAT_ID, CLASS, ADMIN_ID
pytest                        # 106 тестов, сеть не используется
python -m bot.bot
```

При старте бот сразу делает первый опрос и сохраняет снимок в SQLite
(уведомления при первом запуске не отправляются), затем поднимает планировщик.

## Docker

```bash
cp .env.example .env   # заполнить
docker compose up -d --build
docker compose logs -f
docker compose restart  # после правки .env
```

База лежит в томе `./data/bot.db`, логи ограничены ротацией json-file.

## Деплой на VPS

```bash
ssh user@host
git clone https://github.com/Egkaz/sunc-schedule-bot.git /opt/sunc-schedule-bot && cd /opt/sunc-schedule-bot
cp .env.example .env && nano .env
docker compose up -d --build
```

Автозапуск обеспечивает `restart: unless-stopped`. Обновление:

```bash
git pull && docker compose up -d --build && docker compose restart
```

Вариант без Docker — systemd:

```ini
# /etc/systemd/system/sunc-bot.service
[Unit]
Description=SUNC schedule bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/sunc-schedule-bot
EnvironmentFile=/opt/sunc-schedule-bot/.env
ExecStart=/opt/sunc-schedule-bot/.venv/bin/python -m bot.bot
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now sunc-bot
journalctl -u sunc-bot -f
```

## Команды

Работают и в чате класса, и в личке:

| Команда | Что делает |
|---|---|
| `/сегодня` | расписание на сегодня |
| `/завтра` | расписание на завтра |
| `/день пн..сб` | ближайший такой день (сегодня, если он впереди) |
| `/класс 10Б [день]` | расписание другого класса (по умолчанию сегодня) |
| `/препод Бондарь [день]` | расписание преподавателя; при нескольких совпадениях перечислит |
| `/аудитория 304 [день]` | расписание аудитории |
| `/помощь` | список команд |

Только для `ADMIN_ID`:

| Команда | Что делает |
|---|---|
| `/проверить` | принудительный опрос и отчёт об изменениях |
| `/статус` | последний успешный опрос, счётчик неудач, размер снимка |
| `/пост` | прислать расписание на завтра в чат немедленно |
| `/дз [день]` | домашнее задание из журнала на день (по умолчанию завтра) |
| `/тема` | запомнить ветку форума: посты и уведомления пойдут туда |

### Формат сообщений

Само расписание (пост на завтра в 15:00, `/пост`, `/сегодня`, `/завтра`, `/день`,
`/класс`, `/препод`, `/аудитория`) отправляется **картинкой-таблицей PNG**
(`bot/render.py`, Pillow) — копией таблицы с сайта СУНЦ:

* шапка зелёная `#339C33`, колонки «Номер урока» и «Урок»;
* рамки `#dadada`, чередование строк, выравнивание по центру;
* строки всегда 1..7, под номером — время звонка;
* в ячейке — как на сайте: `предмет, аудитория, преподаватель`
  (для `/препод` — `предмет, аудитория, класс`, для `/аудитория` — `предмет, преподаватель, класс`);
* изменённые уроки — оранжевым `#ff8a37` (класс `attention`);
* пустой день — блок «Занятий нет».

Если отрисовка невозможна (нет шрифта, сбой Pillow), бот отправляет тот же текст
обычным сообщением.

Сообщение об изменениях и служебные ответы (`/помощь`, `/статус`) — текстом:

```
Изменения в расписании на Пятницу 10Н
1 урок: Химия, Климова Л.И., 309 -> Нет
5 урок: Нет -> Алгебра, Бондарь А.А., 304
```

Текст внутри карточки:

```
Расписание на Четверг 10Н
1 урок (9:00-9:40): Алгебра, Бондарь А. А., 304
3 урок (10:45-11:25): Русский, Корюкалова М.С., 324
```

Параллельные подгруппы склеиваются через «/»:
`1 урок (9:00-9:40): Информатика, Киселев П.Г. / Сандакова С. Л., 206 / 207`.
Пустые уроки пропускаются.

Звонки: 9:00-9:40, 9:50-10:30, 10:45-11:25, 11:40-12:20, 12:35-13:15, 13:35-14:15, 14:35-15:15.

## Как устроено

```
bot/
  config.py     .env → Config, валидация
  fetcher.py    httpx: ретраи с backoff, справочники id, GET ?type=11
  normalize.py  lessons+diffs → {урок, время, предмет, преподаватель, аудитория}
  differ.py     сравнение снимков по слотам 1..7
  formatter.py  тексты сообщений
  render.py     таблица расписания → PNG, как на сайте (Pillow)
  storage.py    SQLite (aiosqlite): снимок, last_ok, счётчик неудач
  service.py    опрос, публикация, запросы по командам
  scheduler.py  APScheduler: опрос + пост в 15:00 (вс–пт)
  handlers.py   команды aiogram 3
  lycreg.py     клиент журнала lycreg: вход, капча, подбор ДЗ по урокам
  bot.py        точка входа, логирование, graceful shutdown
tests/          pytest: differ, formatter, normalize, справочник, хранилище, сборка
```

### Устойчивость

* каждый HTTP-запрос — до 3 попыток с экспоненциальным backoff, таймаут 15 с;
* если опрос не удался 3 раза подряд — одно сообщение `ADMIN_ID`, дальше бот молчит
  до восстановления и не спамит;
* падение Telegram при отправке не срывает опрос (лог + продолжение);
* снимок сохраняется до отправки — дубли невозможны;
* `SIGINT`/`SIGTERM` → планировщик, HTTP-клиент и БД закрываются аккуратно.
